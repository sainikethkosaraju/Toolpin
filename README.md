# toolpin

The lockfile and forgery-proof approvals for MCP, library first. Toolpin pins every tool by hash and gates every call: changed tools disappear, risky calls pause for a human, and an approval is valid for **one exact call**.

```bash
pip install -e .[dev]
python -c "import toolpin; print(toolpin.__version__)" && pytest -q        # 29 tests, incl. forgery/replay/rug-pull
toolpin corpus                                                             # 178-case attack/benign corpus with misses listed
```
```python
from mcp.server.mcpserver import MCPServer
from toolpin.middleware import GateConfig, guard
from toolpin.lockfile import Lockfile
from toolpin.policy import YamlPolicy
from toolpin.approvals import Approvals

server = MCPServer("demo")            # ... register tools ...
lock = Lockfile.lock(await server.list_tools())          # review, then commit toolpin.lock
guard(server, GateConfig(lock, YamlPolicy.load("policy.yaml"),
                         Approvals(os.environ["TOOLPIN_APPROVAL_SECRET"])))
```

## How it works
```
client -> [Gate: lock check -> policy (default deny) -> constraints -> budgets -> approval -> forward -> output cap] -> tool
                                      every decision -> hash-chained audit
```
Approval protocol: [docs/approval-protocol.md](docs/approval-protocol.md). Modern clients get an MRTR `InputRequiredResult`; legacy clients are denied or routed to `toolpin approve-call`.

## Results (every number is generated or tested)
| Claim | Evidence |
| --- | --- |
| Any post-lock change (description, schema, annotation, title, outputSchema, look-alike char, extra/duplicate tool) is blocked | [tests/test_core.py](tests/test_core.py), corpus `rp-*` |
| Approval forgery, replay, argument tampering, wrong tool/principal, expiry, wrong key: all rejected; each nonce once | [tests/test_core.py](tests/test_core.py), [tests/test_gate.py](tests/test_gate.py), corpus `ap-*` |
| Confusion matrix per control, misses and false positives listed | [corpus/RESULTS.md](corpus/RESULTS.md) (regenerated by `toolpin corpus`; a test fails if stale) |
| Gate overhead | median +0.14 ms/call in-memory ([bench/overhead.py](bench/overhead.py), [docs/limits.md](docs/limits.md)) |
| Cedar gives the same decisions as the YAML engine on a shared set | `test_cedar_matches_yaml_on_shared_set` |

Structural controls (lockfile, approval, handle, identity) show 0 misses / 0 false positives on this corpus. Heuristic controls do not: `scan` recall 0.72 / precision 0.81, `args` recall 0.78, `url` recall 0.82, `policy` recall 0.70, `shadow` recall 0.78 (see the file for exactly which cases). The corpus is author-written and small: evidence, not proof.

## Limitations (plain words)
[docs/threat-model.md](docs/threat-model.md) lists what is not covered. Highlights: a tool that was malicious at lock time stays malicious; `scan` is a heuristic; SSRF is static; nonce store is per-process; **proxy modes (stdio/HTTP) are not implemented**; the 40-task with/without-Toolpin agent benchmark was not run (needs model keys and nightly collection).

## What I would do differently
Ship the proxy mode with a sandboxed spawn, add a shared nonce store, and run the benchmark with real models.

## Configuration
Copy `.env.example` to `.env` (git-ignored). `TOOLPIN_APPROVAL_SECRET` (>= 32 chars) is required for approvals and has no default.
